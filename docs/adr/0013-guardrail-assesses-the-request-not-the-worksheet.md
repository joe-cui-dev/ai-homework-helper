# Guardrail Assesses the Request, Not the Worksheet

Homework calls tag what is being asked — the parent's typed question, the list of questions to coach — in Bedrock `guardContent` blocks, and leave quoted source material outside the tagged span: Page Context extracted from a photographed worksheet, and the prior Page Context replayed on an append. The guardrail's input policies then judge the request rather than the textbook. The model still receives every block; only the guardrail's view narrows. Untagged Converse messages are assessed in full, which made the guardrail read a worksheet as if the parent had typed it: a Year-4 pirate-dialogue comprehension exercise tripped the OffTopic topic policy and the PROMPT_ATTACK filter, and the whole submission was blocked with "Please ask me a homework question!".

Tagging alone is not sufficient, because the OffTopic definition itself conflated the request with the material by naming "creative fiction" off topic. The definition now judges the request and states that questions about fiction studied at school are schoolwork. Both halves are needed: the question list alone still blocked under the old definition, and the passage combined with the question list still blocks under the new one.

Every guarded message must carry exactly one `guardContent` block, including when the parent typed nothing — with none, Bedrock reverts to assessing the whole message, which is the behaviour being avoided. Output assessment is unaffected by input tagging, so model-generated coaching text stays fully screened. The uploaded image itself is not assessed: the content policy is configured for text, so page images pass through unscreened both before and after this change.
